# Fragment in SAPUI5

A **Fragment** is a **reusable UI definition without its own controller**.

Key points:

- No controller
- No lifecycle hooks like `onInit`
- Reusable across views
- Ideal for dialogs, popovers, simple UI blocks

Fragments can be:

- **XML fragments** (most common)
- JS fragments
- HTML fragments (rare)

## Why Use Fragments?

Without fragments:

- Duplicate dialog/popover code
- Harder maintenance
- Larger views

With fragments:

- Reusability
- Cleaner views
- Centralized UI logic
- Better performance (lazy loading)

## XML Fragment – Dialog Example

### 1. Fragment File

`ConfirmDialog.fragment.xml`

```xml
<core:FragmentDefinition
  xmlns="sap.m"
  xmlns:core="sap.ui.core">

  <Dialog
    id="confirmDialog"
    title="Confirmation">

    <Text text="Are you sure you want to proceed?" />

    <beginButton>
      <Button text="OK" press="onConfirm"/>
    </beginButton>

    <endButton>
      <Button text="Cancel" press="onCancel"/>
    </endButton>

  </Dialog>
</core:FragmentDefinition>
```

### 2. Using Fragment in Controller

```jsx
async onOpenDialog() {
  this.oDialog ??= await this.loadFragment({
    name: "ui5.walkthrough.view.HelloDialog"
  });
  this._oDialog.open();
},
```

### 3. Event Handling

Even though the fragment has no controller:

- Events (`press="onConfirm"`) are handled by t**he hosting controller**

```jsx
onConfirm: function () {
  this._oDialog.close();
},

onCancel: function () {
  this._oDialog.close();
}

```

Extend it:

```jsx
return BaseController.extend("com.app.controller.Home", {});
```
