# Formatters in SAPUI5

A **formatter** is a JavaScript function that **transforms model data** into a **UI-friendly format**.

## 1. Simple Formatter (Single Value)

### Formatter File (formatter.js)

```jsx
return {
  uppercase: function (sValue) {
    return sValue ? sValue.toUpperCase() : "";
  },
};
```

### XML View Usage

```xml
<Text text="{path: 'name', formatter: '.formatter.uppercase'}" />

```

## 2. Composite Formatter (Multiple Values)

### XML View

```xml
<Text text="{
  parts: [
    {path: 'firstName'},
    {path: 'lastName'}
  ],
  formatter: '.formatter.fullName'
}" />
```

### Formatter Function

```jsx
fullName: function (sFirst, sLast) {
  return sFirst + " " + sLast;
}
```

## 3. Formatter for Visibility / Enablement

Show/hide or enable/disable UI elements.

### XML View

```xml
<Button
  text="Approve"
  visible="{path: 'status', formatter: '.formatter.isApprovable'}" />
```

### formatter.js

```jsx
isApprovable: function (sStatus) {
  return sStatus === "PENDING";
}

```

## 4. Formatter for State / Semantic Color

ObjectStatus, MessageStrip, ProgressIndicator state.

### XML View

```xml
<ObjectStatus
  text="{status}"
  state="{path: 'status', formatter: '.formatter.statusState'}" />

```

### formatter.js

```jsx
statusState: function (sStatus) {
  switch (sStatus) {
    case "SUCCESS": return "Success";
    case "ERROR": return "Error";
    case "WARNING": return "Warning";
    default: return "None";
  }
}

```

## 5. Formatter for Date Formatting

Format backend dates for display.

### XML View

```xml
<Text text="{path: 'createdOn', formatter: '.formatter.formatDate'}" />

```

### formatter.js

```jsx
formatDate: function (oDate) {
  if (!oDate) {
    return "";
  }
  return sap.ui.core.format.DateFormat
    .getDateInstance({ pattern: "dd/MM/yyyy" })
    .format(oDate);
}

```

## 6. Formatter for Numbers / Currency

Format amounts, quantities, prices.

### XML View

```xml
<Text text="{path: 'amount', formatter: '.formatter.formatAmount'}" />

```

### formatter.js

```jsx
formatAmount: function (fAmount) {
  return fAmount
    ? fAmount.toFixed(2) + " USD"
    : "0.00 USD";
}

```

> ⚠️ Better practice: use sap.ui.model.type.Currency for inputs.

## 7. Formatter Using i18n Texts

Dynamic text with translations.

### XML View

```xml
<Text text="{path: 'status', formatter: '.formatter.statusI18n'}" />

```

### formatter.js

```jsx
statusI18n: function (sStatus) {
  var oBundle = this.getOwnerComponent()
    .getModel("i18n")
    .getResourceBundle();

  return oBundle.getText("status_" + sStatus);
}

```

## 8. Formatter with Model Access

Conditional formatting based on multiple models.

### XML View

```xml
<Text text="{path: 'price', formatter: '.formatter.priceText'}" />

```

### formatter.js

```jsx
priceText: function (fPrice) {
  var sCurrency = this.getView()
    .getModel("config")
    .getProperty("/currency");

  return fPrice + " " + sCurrency;
}

```

## 9. Formatter in JavaScript (Controller Binding)

### Use case

Dynamic binding at runtime.

```jsx
oText.bindText({
  path: "status",
  formatter: function (sStatus) {
    return sStatus === "A" ? "Active" : "Inactive";
  },
});
```

## 10. Formatter vs Expression Binding (Comparison)

### Expression Binding (Simple Logic)

```xml
<Text text="{= ${price} > 100 ? 'High' : 'Low'}" />

```

### Formatter (Complex Logic)

```xml
<Text text="{path: 'price', formatter: '.formatter.priceCategory'}" />

```

## 11. Formatter for Table Columns

Format table cell values.

```xml
<ColumnListItem>
  <Text text="{path: 'quantity', formatter: '.formatter.qtyText'}" />
</ColumnListItem>

```

## 12. Global Formatter (Reuse Across Views)

### formatter.js

```jsx
sap.ui.define([], function () {
  "use strict";
  return {
    yesNo: function (bValue) {
      return bValue ? "Yes" : "No";
    },
  };
});
```

### Controller

```jsx
formatter: Formatter;
```

### XML View

```xml
<Text text="{path: 'approved', formatter: '.formatter.yesNo'}" />

```

# Formatter vs Type in SAPUI5

## Core Difference (One-Line)

> Formatters are for display only (one-way), while Types handle user input, validation, parsing, and two-way binding.

## 1. Formatter with Input Control (Wrong for User Input)

### Scenario

You want to format a price to **2 decimals** in an `<Input>` field.

### XML View (Using Formatter)

```xml
<Input
  value="{path: 'price', formatter: '.formatter.formatPrice'}" />

```

### formatter.js

```jsx
formatPrice: function (fPrice) {
  return fPrice ? fPrice.toFixed(2) : "0.00";
}

```

### What Happens?

| Action           | Result                            |
| ---------------- | --------------------------------- |
| Model → UI       | ✔ Price is formatted              |
| User edits input | ❌ Model is NOT updated correctly |
| Validation       | ❌ Not possible                   |
| Parsing input    | ❌ Not possible                   |

⚠️ **Problem:**

Formatter output is **read-only**.

TwoWay binding **breaks silently**.

## 2. Type with Input Control (Correct Approach)

### XML View (Using Type)

```xml
<Input value="{
  path: 'price',
  type: 'sap.ui.model.type.Float',
  formatOptions: {
    minFractionDigits: 2,
    maxFractionDigits: 2
  }
}" />

```

### What Happens?

| Action           | Result                 |
| ---------------- | ---------------------- |
| Model → UI       | ✔ Formatted value      |
| User edits input | ✔ Parsed back to model |
| Validation       | ✔ Automatic            |
| TwoWay binding   | ✔ Works correctly      |

## 3. Real Example: Date Input

### Using Formatter (Wrong)

```xml
<DatePicker
  value="{path: 'orderDate', formatter: '.formatter.formatDate'}" />

```

### Problems

- User input cannot be parsed
- No validation
- Model update fails

### Using Type (Correct)

```xml
<DatePicker value="{
  path: 'orderDate',
  type: 'sap.ui.model.type.Date',
  formatOptions: {
    pattern: 'dd/MM/yyyy'
  }
}" />

```

✔ Supports:

- User typing date
- Validation
- Model updates

## 4. Formatter for Display Controls (Correct Usage)

### Example: Text Control

```xml
<Text text="{path: 'price', formatter: '.formatter.formatPrice'}" />

```

✔ Perfect use case

✔ Display-only

✔ No user input required

## 5. Side-by-Side Comparison

| Feature            | Formatter  | Type       |
| ------------------ | ---------- | ---------- |
| Direction          | Model → UI | Model ↔ UI |
| TwoWay binding     | ❌ No      | ✔ Yes      |
| User input parsing | ❌ No      | ✔ Yes      |
| Validation         | ❌ No      | ✔ Yes      |
| Error messages     | ❌ No      | ✔ Yes      |
| Input controls     | ❌ Avoid   | ✔ Use      |
| Display controls   | ✔ Yes      | ✔ Yes      |

## 6. Currency Example (Real Fiori Scenario)

### ❌ Formatter Way

```xml
<Input value="{path: 'amount', formatter: '.formatter.amountText'}" />

```

### ✅ Correct Type Way

```xml
<Input value="{
  parts: [
    {path: 'amount'},
    {path: 'currency'}
  ],
  type: 'sap.ui.model.type.Currency'
}" />

```

✔ Automatically formats

✔ Parses user input

✔ Handles locale

## 7. Validation Example with Type

```xml
<Input value="{
  path: 'quantity',
  type: 'sap.ui.model.type.Integer',
  constraints: {
    minimum: 1
  }
}" />

```

✔ Shows validation error

✔ Prevents invalid model updates

✔ No formatter can do this

## 8. Rules (Very Important)

### Rule 1

> Never use formatters on editable Input fields.

### Rule 2

> Use Types whenever user input must be validated or written back.

### Rule 3

> Use formatters only for display logic.
