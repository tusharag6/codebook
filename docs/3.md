# Models in SAP Ui5

**Models** are the layer that hold application data and provide it to the UI via **data binding**.

They are a container for storing data.

UI controls **never store data themselves** — they **read data from models** using **binding**.

```
Model  →View(XML)  →Control(Text,Input,List)
```

## 1. JSONModel

- Holds data in **JavaScript Object Notation (JSON)**
- Data is kept **client-side (in memory)**
- Very fast and flexible

### Use Cases

- UI state (visibility, enablement)
- Temporary data
- Mock data
- Small to medium datasets

### Pros / Cons

- Fast, simple
- No built-in server communication

### STEP 2: Load `minerals.json` as a JSONModel

We **do NOT** read JSON files in the view.

Models are loaded in **Component.js** (best practice).

**File:** `webapp/Component.js`

Add **JSONModel import**:

```jsx
sap.ui.define(
  [
    "sap/ui/core/UIComponent",
    // Add JSON Model Import
    "com/capgemini/z3708miningjson/model/models",
    "sap/ui/model/json/JSONModel",
  ],
  (UIComponent, models, JSONModel) => {
    "use strict";

    return UIComponent.extend("com.capgemini.z3708miningjson.Component", {
      metadata: {
        manifest: "json",
        interfaces: ["sap.ui.core.IAsyncContentCreation"],
      },

      init() {
        // call the base component's init function
        UIComponent.prototype.init.apply(this, arguments);

        const sUrl = sap.ui.require.toUrl(
          "com/capgemini/z3708miningjson/model/minerals.json",
        );
        const oModel = new JSONModel(sUrl);
        this.setModel(oModel, "minerals");

        // set the device model
        this.setModel(models.createDeviceModel(), "device");

        // enable routing
        this.getRouter().initialize();
      },
    });
  },
);
```

### STEP 3: Bind JSON Array to a List

Now let’s display all minerals.

```xml
<List
    id="_IDGenList1"
    items="{minerals>/Locations}"
    itemPress="onRowPress"
>
    <items>
        <StandardListItem
            id="_IDGenStandardListItem"
            title="{minerals>LocationName}"
            description="{minerals>Region}"
            type="Active"
        />
    </items>
</List>

```

## 2. OData Model

For backend service integration

SAPUI5 supports **OData V2 and V4 models**.

Connects to **OData V2 services** (SAP Gateway)

TwoWay binding supported

Batch, CRUD, function imports

## 3. XMLModel

- Data stored in **XML format**
- Read-only in most cases

### Creation

```jsx
var oModel = new sap.ui.model.xml.XMLModel();
oModel.loadData("data.xml");
this.getView().setModel(oModel);
```

### XML Binding

```xml
<Text text="{/user/name}" />
```

### Use Cases

- Configuration files
- Legacy XML data
- Not common in modern apps

## 4. ResourceModel (i18n Model)

For internationalization (translations)

Loads **.properties** files

Read-only

Special binding syntax

```xml
<Text text="{i18n>appTitle}" />
```

### Use Cases

- Translated texts
- Language support
