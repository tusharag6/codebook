SAP Ui5 is a JS framework developed by SAP to build responsive and user friendly web interfaces for business applications.

- It is JavaScript based framework
- It is based on MVC architecture. Model(data layer), View(UI layer), Controller(Logic layer).
- Responsive UI
- Pre-built rich ui controls: list, tables, etc.

SAP Fiori is UX design concept, it defines how the app should look and feel. It uses Ui5.

## Typical UI5 App Structure

```
my.ui5.app/
│
├── webapp/
│   ├── controller/
│   │   └── Main.controller.js
│   │
│   ├── view/

│   │
│   ├── model/
│   │   └── models.js
│   │
│   ├── i18n/

│   │
│   ├── css/
│   │   └── style.css
│   │
│   ├── Component.js

├── test/
│   ├── unit/
│   └── integration/

```

Now let’s understand **what each folder/file actually does**.

### `webapp/`

This is where **your UI5 app lives**.

### `view/`

Contains the **UI layout** (what the user sees).

Written mostly in **XML**.

Defines **buttons, tables, forms, pages**

### `controller/`

Contains the **logic behind the UI**.

Handles button clicks, navigation, data logic

### `model/`

Handles **data**.

Common models:

- OData Model (from SAP backend)
- JSON Model (local data)

Connects UI to backend data

### `i18n/`

Used for **translations** (language support).

Example:

- `i18n.properties`

```
title=Approve Leave Requests
buttonApprove=Approve
```

Makes the app multilingual

### `Component.js`

The **entry point** of the UI5 app.

Responsibilities:

- Initializes the app
- Loads models
- Handles routing

Think of it as the **brain of the app**

### `manifest.json`

This is the **app configuration file**.

Contains:

- App name & ID
- Data sources (OData service)
- Models
- Routing & navigation
- Fiori app settings

Called the **“app descriptor”**

Almost everything important is declared here.

### `index.html`

The **startup file**.

- Loads UI5 framework
- Starts the app

Usually very small.

## Difference between `index.html` and `component.json`

### What `index.html` Actually Does

`index.html` is **plain HTML**.

Typical responsibilities:

- Load the **SAP UI5 framework**
- Tell UI5 **which app to run**
- Create a place (`<div>`) where the app will appear

Example (simplified):

```html
<script
  src="https://ui5.sap.com/resources/sap-ui-core.js"
  data-sap-ui-theme="sap_fiori_3"
  data-sap-ui-resourceroots='{
    "my.app": "./"
  }'
></script>

<div id="content"></div>
```

### Key point:

- `index.html` **does not know your app logic**
- It only **boots UI5**

### What `Component.js` Actually Does

`Component.js` is **UI5 code**.

Typical responsibilities:

- Initialize the **application**
- Load **models**
- Configure **routing**
- Create the **root view**

Example (simplified):

```jsx
init: function () {
   UIComponent.prototype.init.apply(this, arguments);
   this.getRouter().initialize();
}

```

### Key point:

- `Component.js` is where **your app truly begins**
