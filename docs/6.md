# Controller Lifecycle Methods

SAPUI5 provides **four core lifecycle hooks**:

1. `onInit()`
2. `onBeforeRendering()`
3. `onAfterRendering()`
4. `onExit()`

These belong to `sap.ui.core.mvc.Controller`.

## Lifecycle Order (Very Important)

The **execution sequence** is:

```
Controller created
   ↓
onInit()
   ↓
View rendering starts
   ↓
onBeforeRendering()
   ↓
View rendered to DOM
   ↓
onAfterRendering()
   ↓
(View may re-render multiple times)
   ↓
onExit() (when view is destroyed)

```

## 1. onInit() – Initialization Phase

### When is it called?

- Called **once** when the Controller is instantiated
- Happens **before the View is rendered**
- View controls exist, but DOM does NOT

### Use `onInit()` for:

- Setting models
- Initializing variables
- Attaching route handlers
- Reading startup parameters
- Calling backend services (OData)

### Do NOT:

- Access DOM elements
- Use jQuery selectors on UI controls

### Example

```jsx
onInit: function () {
    var oModel = new sap.ui.model.json.JSONModel({
        name: "SAPUI5"
    });
    this.getView().setModel(oModel);

    var oRouter = sap.ui.core.UIComponent.getRouterFor(this);
    oRouter.getRoute("detail").attachPatternMatched(this._onRouteMatched, this);
}
```

### Key Point

- Best place for **setup logic**

## 2. onBeforeRendering() – Pre-Render Hook

### When is it called?

- Called **every time before the View is rendered**
- Called **multiple times** (not just once)

### Use `onBeforeRendering()` for:

- Last-minute data updates
- Adjusting bindings before UI refresh
- Updating visibility or enablement logic

### Avoid:

- Heavy logic
- Backend calls
- Event attachments (will duplicate)

### Example

```jsx
onBeforeRendering: function () {
    var bEditable = this.getView().getModel().getProperty("/editable");
    this.byId("saveBtn").setEnabled(bEditable);
}
```

### Important Note

This method can be triggered **many times**, so keep it **lightweight**

## 3. onAfterRendering() – Post-Render Hook

### When is it called?

- Called **after the View is rendered into the DOM**
- Called **every time the View re-renders**

### Use `onAfterRendering()` for:

- DOM manipulation (only if unavoidable)
- jQuery plugins
- Measuring UI sizes
- Focus handling

### Avoid:

- Model initialization
- Repeated event attachments
- Business logic

### Example

```jsx
onAfterRendering: function () {
    var oInput = this.byId("nameInput");
    oInput.focus();
}
```

### Warning

Direct DOM manipulation is **not recommended** unless absolutely necessary.

## 4. onExit() – Cleanup Phase

### When is it called?

- Called **once** when the View is destroyed
- Happens when:
  - App is closed
  - Navigation removes the view
  - Component is destroyed

### Use `onExit()` for:

- Detaching event handlers
- Clearing timers
- Destroying custom objects
- Memory cleanup

### Example

```jsx
onExit: function () {
    if (this._intervalId) {
        clearInterval(this._intervalId);
    }
}
```

### Key Point

Prevents **memory leaks**
