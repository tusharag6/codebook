### How the Startup Flow Really Works

Here’s the **actual sequence**:

1️⃣ **Bootstrap**

- Opens `index.html` and loads (`sap-ui-core.js`)

2️⃣ **UI5 reads the descriptor**

- Looks for `manifest.json`
- Understands app structure & config

3️⃣ **Component is created**

- UI5 instantiates `Component.js`
- Automatically applies config from manifest

5️⃣ `Component.js` initializes models, routing, views

6️⃣ App UI appears on screen

## Bootstrapping In SAP Ui5

Bootstrap = It is the process of starting something

In SAP Ui5, Bootstrap, means loading and initializing the Ui5 framework in browser.

This happens in **`index.html`** (or Fiori Launchpad internally).

Example (simplified):

```html
<script
  src="resources/sap-ui-core.js"
  data-sap-ui-theme="sap_fiori_3"
  data-sap-ui-libs="sap.m"
  data-sap-ui-resourceroots='{
    "my.app": "./"
  }'
></script>
```

### What happens here:

- Browser loads **sap-ui-core.js**
- UI5 framework initializes
- Theme, libraries, and app namespace are set
- UI5 runtime becomes available

At this point our app is not running yet, just Ui5 framework is ready.

## Descriptors

Descriptors is metadata file that describes the app.

It is `manifest.json` file.

This is why Ui5 apps are called metadata driven applications

# MVC Architecture

MVC is an architectural pattern used in SAP Ui5 used for separation of concerns.

## Model : Data Layer

Manages application data.

### **Types of Model:**

- JSON Model: Client-side purpose
- XML Model: XML based data
- OData Model: Backend Data(SAP Gateway)
- Resource Model: i18n (Translation)

**Responsibility:**

- Holds no UI logic.
- Support two-way binding.

**Example**

```jsx
var oModel = new sap.ui.model.json.JSONModel({
  name: "John",
  age: 25,
});
this.getView().setModel(oModel);
```

**Binding in View**

```tsx
<Text text="{/name}" />
```

## View: UI Layer

Defines how UI looks

### Types of Views:

- XML View
- JS View
- JSON View
- HTML View

**Responsibility:**

- Uses **data binding** to connect to Models
- No business logic
- Minimal event handling (delegates to Controller)

**Example XML View**

```xml
<mvc:View
controllerName="myApp.controller.Main"
xmlns:mvc="sap.ui.core.mvc"
xmlns="sap.m">

<VBox>
<Input value="{/name}" />
<Button text="Click Me"press="onPress" />
</VBox>

</mvc:View>
```

## Controller : Logic Layer

Contains logic of the application

**Responsibilities**

- Handles user events (click, change, submit)
- Updates the Model
- Navigates between views
- Calls backend services

**Example Controller**

```jsx
sap.ui.define(["sap/ui/core/mvc/Controller"], function (Controller) {
  "use strict";

  returnController.extend("myApp.controller.Main", {
    onInit: function () {
      // Initialization logic
    },

    onPress: function () {
      var oModel = this.getView().getModel();
      oModel.setProperty("/name", "SAP UI5");
    },
  });
});
```

## How MVC Works Together in SAPUI5

1. **View loads**
2. **Controller is instantiated**
3. **Model is attached to View**
4. UI binds to Model
5. User interacts with UI
6. Event triggers Controller method
7. Controller updates Model
8. UI updates automatically via data binding

**No direct View → Model manipulation**
